# Documentation-only APP-00A CI implementation plan

> Execute with `superpowers:subagent-driven-development` and retain source-bound
> verification before reporting completion.

**Goal:** shorten eligible prose-only PRs by skipping four APP-00A Windows
workers, preserving the `validate` check and all required lightweight checks.

**Design:** [task scope and design](../specs/2026-11-25-docs-pr-ci-design.md).

**Baseline:** `bcdc5f54dc51e7201ce265fcb900b582ebdc8500` after PR #148.

## Global Constraints

- Keep the `validate` job name and unconditional `always()` gate.
- Preserve all four existing worker steps, commands, environment, timeouts,
  toolchain pins and artifacts; change only their job-level needs/condition.
- Preserve workflow triggers, concurrency, `contents: read`, and all other
  workflow files. Do not add workflow-level path filters or skip overrides.
- Only a complete, source-bound, nonempty pull-request diff of allowlisted
  ordinary prose blobs can skip workers. Main pushes always execute full CI.
- Keep immutable business, link, and E-SIM checks running on both routes.
- A missing, failed, cancelled, skipped, malformed, or mismatched classifier
  must never make `validate` green. Full mode requires four successes; docs
  mode requires four explicit skips and valid positive proof.
- Keep business contracts, runtime tests, retry budgets and acceptance rules
  unchanged. Docs success explicitly means runtime workers NOT_RUN.
- Create and verify an implementation PR. Do not merge it as part of this task.

## Task 1: Classifier and native Git regression tests

**Own:** `tools/classify_app00a_pr.py`, `tests/ci/test_app00a_classification.py`.

Implement the exact interface and 16-path policy in the design. Use only the
Python standard library and Git. Bound Git work, parse raw NUL records strictly,
inspect the complete PR and integration comparisons, and emit a conservative
full receipt on comparison uncertainty. Retain safe single-line output and
the artifact/job-summary interface.

Write failing behavioral tests before implementation. Test allowed prose,
mixed changes, source in an earlier commit followed by docs, unknown/new docs,
case/path oddities, executable/symlink/gitlink/type changes, additions,
deletions, source-to-docs and docs-to-source moves, empty diff, missing/shallow
history, ambiguous merge bases, merge-parent/checkout mismatch, base movement,
and non-PR events. Use real temporary Git graphs where they establish range
or mode correctness; inject only otherwise unrepresentable malformed output.
Verify the real CLI receipt and output files. Expected values come from test
intent, not the production allowlist.

Run the focused classifier suite, record RED/GREEN and self-review in the
task report, then hand off for independent review. Controller owns commits
because parallel tasks share this already-isolated worktree.

## Task 2: Aggregate and workflow integration

**Own:** `tools/verify_app00a_jobs.py`, `tests/ci/test_app00a_jobs.py`,
`.github/workflows/app00a.yml`.

Add the classifier job with its existing lightweight checks and receipt
artifact. Set its outputs from the classification step. Add four worker
prerequisites and the cancellation-aware conditional described in the design.
Expand `validate` dependencies and pass the four context variables to its gate.

Extend `evaluate_needs(raw_needs, *, event_name=None, base_sha=None,
source_head_sha=None, workflow_sha=None)` to enforce the design's two exact
routes. Main passes the four environment values explicitly. Share the
classifier's record predicate, supporting both module imports and the existing
direct-script CLI. Parse nested receipt JSON using the same duplicate-key and
non-JSON-literal rejection as `needs`.

Retain every original negative regression and add classifier failures,
receipt schema/version/identity errors, full worker skip/failure, docs on push,
invalid path/mode proof, and mixed docs worker states. Assert meaningful CLI
exit status and output. Run focused tests, actionlint, and compare every
baseline worker step and companion workflow with the candidate. Record
RED/GREEN, changed files and self-review in the report.

## Task 3: Documentation, review, live verification and PR

**Own:** `docs/roadmap/docs-pr-ci.md`, the relevant CI-note cross-link,
this plan and its design, PR metadata and scratch evidence.

Document eligibility, full-CI defaults, source bindings, missing runtime
evidence on docs success, maintenance responsibility, and how to review the
classification receipt. Do not claim a speed target as measured before CI.

Run combined Python tests, business/E-SIM checks, YAML/actionlint, whitespace,
and preservation checks once the final candidate is integrated. Independently
review the complete diff, fix substantive findings, and reverify affected
behavior. Publish a PR based on fresh main; observe the exact source's full
hosted CI and receipt. Then run the temporary draft child PR described in the
design to prove real docs skips; close it without merge. Measure both runs,
preserve URLs/SHAs/attempts/artifacts in the PR body, and report the final
implementation status and any remaining limitations.
