# APP-02B LAB — Security and Runtime Increments

**State:** PLAN_ONLY / IMPLEMENTATION_NOT_STARTED. Baseline `16d96c71a7967c216ebfa599693807a2b54e7435`, 2026-11-19.

**Goal:** Connect real B3/B4/B5 authority to a narrow lab API, original durable journal, Worker, CASE and audit.

**Architecture/stack:** [Design and contracts](design.md), .NET 10/SQL Server, PowerShell/Linux and Python as assigned below. **Global constraints:** [Design sections 1–7](design.md); immutable business baseline, retained guards, source-bound admission and no automatic physical acceptance. **Review focus:** [five cross-cutting risks](design.md#8-five-review-risks-and-required-ownership). **Execution/commands:** [Codex handoff](codex-handoff.md). A `Create/New` path or API below is proposed, not a claim that it already exists.

Every increment must add meaningful regression/negative tests for its owned invariant, verify relevant retained suites, preserve failed evidence, and record source-only versus live results separately. Commands for new components apply only after that increment implements them.

## Shared design and merge rules

- Keep B.3 Identity, B.4 Registry, B.5 fence **and every tenant DB participating in a fenced SQL effect on one supported SQL Server instance**. The current design uses one `SqlConnection` and one `SqlTransaction` with three-part names; it does not provide distributed transactions.
- Preserve `SqlAuthorizationFence.ExecuteAsync<T>(AuthorizationContext, SqlControlPlaneGuards, Func<SqlConnection,SqlTransaction,CancellationToken,Task<T>>, CancellationToken)` as internal and LocalDB-only. Do not remove its safety guard to admit the laptop. Introduce a separate typed command surface which reuses the reviewed SQL authority procedures and always requires current B3/B4/B5 authority.
- Keep existing `FmcgDms.Preprod.Api` and `FmcgDms.Preprod.Worker` entrypoints and defaults `FOUNDATION_ONLY / NO_GO`; do not add dispatch or command routes there. Source merge is not activation. Create **separate** `FmcgDms.Preprod.Lab.Api` and `FmcgDms.Preprod.Lab.Worker` hosts reusing the same new typed command kernel and real B3/B4/B5 authority libraries. A `LAB=true` flag alone is insufficient. Lab commands require the roadmap's explicit, source-bound environment authorization artifact, two approved nonproduction database identities, enabled lab feature, and permitted synthetic fixture identities. Never introduce a default approval or consume a caller's `TenantId`, connection string, role, MakerId or epoch as authority.
- Use `LabRunContext` supplied by the parent plan: run/environment/source/fixture/config/host identities, UTC and mode. It is provenance, **not** an authorization token. Compare it against the externally approved lab profile before any mutation.
- A source PR may complete its reviewed implementation/CI criteria while #53/#56 remain open for operational evidence. No increment inherits an old Owner source-only exception. PR #74 is still Draft, so an approved source-integration disposition for that candidate must precede using it as a merged dependency. Do not require closing #53 before implementing the code needed to satisfy #53; use explicit `SOURCE_READY` versus `PHYSICAL_NOT_VERIFIED` milestones.
- Use the explicit project form for Microsoft Testing Platform in new handoffs (some existing workflows use the supported positional form): `dotnet test --project <project.csproj> -c Release -- --report-trx`. Do not copy VSTest `--filter` assumptions. Use project-level invocations and discover supported test selection through that project's `-- --help` when needed. Every new security test must be observed failing before its fix, then passing, and captured on the final SHA.
- New full-SQL tests live in **new** `tests/FmcgDms.Preprod.Lab.SqlServer.Tests/`. They must require an approved private SQL instance, run-owned marker and exact database allowlist; existing LocalDB guards remain unchanged. CI full-SQL fixtures are disposable and report CI evidence only. Physical/lab evidence is collected by an observer with separate credentials.

**Status:** PLANNED. **PR boundary:** one independently reviewed PR. **Source/API dependencies:** LAB-S01. Live setup/approval requirements are additional and do not convert source merge into acceptance.

Access validation must deny a restored B3 session whose durable epoch is newer or unavailable. Protected command execution will repeat the check under its own COMMIT lock; authentication alone is not a write fence.

**Exit/evidence:** real SQL session/grant/watermark before/after plus HTTP and peer no-write evidence for B01-02 and part of B01-06.
