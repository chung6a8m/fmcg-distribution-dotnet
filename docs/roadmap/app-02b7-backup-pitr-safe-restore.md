## Architecture and authority

1. **Backup principal** runs from an approved isolated operator host using independent SQL credentials; invokes `scripts/Invoke-App02B7Backup.ps1` after target/tenant/certificate/change approval and independently approved current B.4 BindingId/Version. The script derives `FmcgPpT_<TenantId:N>`, pins SQL Server identity, requires FULL recovery and B.4 binding marker, SQL Server certificate encryption AES-256, CHECKSUM and RESTORE VERIFYONLY. Pre-existing SQL-side backup media are denied before `WITH INIT` under a per-tenant session lock. Output is **encrypted local SQL staging only**; it is *not* an off-host or accepted recovery receipt. The script does not change RECOVERY mode, create a certificate, provision a tenant, write a password, ship objects, or schedule jobs. A DBA owns these separately.
2. **Schedule target**: successful daily FULL (regular, not COPY_ONLY) <=24 hours, differential <=6 hours, log <=5 minutes; independently monitor actual UTC msdb backupset/backupmediafamily and SQL FULL recovery, LSN first/last/checkpoint/differential base and recovery fork. Backup scheduler, off-host object-store vendor, immutable object storage, independent transfer, SQL certificate/KeyId/Version and Vault recovery ACL are operator infrastructure **not provisioned in this PR**. A missing real receipt/key or any gap is FAIL/NOT_VERIFIED, never estimated PASS.
3. **Inventory witness**: `B7BackupChain.Inspect` consumes a separately independently produced msdb + off-host manifest, requires consistent tenant DB identity, encrypted/checksummed off-host objects, decrypt witness with separate recovery principal, noncopy full and chain/interval checks. It cannot generate its own evidence; its `AcceptedForOperatorReview` is **not** G-B03 or proof the operator's boolean fields are true. No direct API/Worker or tenant lifecycle dependency is added.
4. **Controlled restore**: fresh B.4 approval puts A in SUSPENDED/nonroutable before restoring. Independent operator chooses approved target point and verifies backup header/LSN, decrypt key history, immutable object checksum and SQL `RESTORE VERIFYONLY`. A is restored in an isolated nonroutable target with no peer overwrites; B continues online. A newly verified B.4 Registry binding/version and tenant marker, current external identity/permission epochs, approval/version and Vault key state are compared *after* restore; never use old restored Control Plane as authority. B.5 issue #53 requires independently durable, monotonic and commit-linearized fence; it remains **OPEN**, so physical reactivation is **NO_GO**.
5. **Outcome safety**: enumerate original APP-02A SourceId/EventId/MessageId, inbound receipts/CASE/inbox/outbox, APP-01 ledger and independent external receiver journal. `B7SafeRestore.Inspect` denies wrong tenant/binding, changed peer hash, missing independent security/key/approval, self review and every UNKNOWN external outcome. A prior COMMITTED receiver result retains its **original** MessageId and must have exactly one effect; an absent externally proven send must have zero, with signed receiver negative. An UNKNOWN without independent evidence => HOLD/CASE/incident, **never** new-ID resend. This is a decision-model contract, not actual receiver integration.
6. **Release barrier**: `B7RestoreInspection.PermitsTenantActivation` is permanently false. Only a future independently approved B.4/B.5/B.7 control-plane operation, physical operator proof and subsequent B.9 acceptance may reenable A; never claim that `ReadyForSeparatePhysicalReview` grants an active tenant. API/Worker remain `FOUNDATION_ONLY/NO_GO` in this PR.
7. **Measurement**: B.1 requires UTC T0 (first unavailable), independently observed latest committed recovered witness, and monotonic T0→T1 until safe API/Worker re-entry. `B7RecoveryTargets.Inspect` fails closed on missing clock/witness/chain/probe and tests numeric design targets **RPO <=900 seconds, RTO <=14400 seconds**. Synthetic fixture numbers are **not actual PREPROD measurements**; RTO ends after verified safe service, not after SQL is online.
