**v0.1 draft · 22/11/2026 · `OWNER_APPROVAL_PENDING / NOT_RUN`**

This matrix covers B quota, credit and load in the [D.0 draft contract](app-02d0-dev-contract.md). Its positive checkpoints run through the existing React workspace, the signed DEV API and actual SQL Server LocalDB. Supplemental fault and concurrency probes use the real API and SQL path. Each required row runs in both tenant A and tenant B unless its scope column specifies a different scope. A/B in that column denotes tenant identity. A/B in rights columns denotes the sales allocation kind.

MAIN pool begins `onHand=100, allocated=0`. Use the accepted C.2 path for **A reservation 40**. Customer and ShipTo records in the peer database have different identifiers.
- Use separate fixture identities for Warehouse issuer/writer, Sales, Finance issuer, approval maker and checker, and a non-assigned Warehouse actor. Map permissions server-side. Proposed credit approval is version 1, cap **100.0000** in `SYNTHETIC_UNITLESS`, with distinct maker, checker and issuer, reviewed before execution. Approved scope is tenant/trip/Customer/pool/currency. Keep an explicit, independent no-credit case on approved cap **0.0000**.
- Proposed controlled UTC clock is **2026-11-22T04:00:00Z**. Use an approved fixture interval `[2026-11-22T03:00:00Z, 2026-11-22T05:00:00Z)` and reviewed-at **02:55 UTC**. Exercise the start/end boundary only in the dedicated guarded DEV clock path. Separate positive and invalid variants so competing test approvals do not leak into later cases.
- Values below are proposed expected data. Review and freeze the fixture and expected-results artifact with SHA-256 before execution. Read actual through a separate read-only SQL identity. Use DB queries by tenant, trip, SKU, source, right and command ID. Do not derive expected values from the service reply. All outcomes below start as `NOT_RUN`.
