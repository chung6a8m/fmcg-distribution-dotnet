## Design

- Retain the original C processing transaction, technical retry accounting, asOf semantics, exponential delays (first 30s), 6-attempt CASE, 24-hour missing-P handling, 15-minute safety tick, outbox claim/ACK, HTTP intake and existing role/tenant/nonce guards. No schema/migration, lock order/isolation, registry, LocalDB bootstrap, deadline or expected oracle changes.
- After every tenant sweep (including a failed outbox/processing sweep), a separate read-only query through the owned synthetic tenant connection returns MIN(NextAttemptAtUtc) only for C in RECEIVED/PENDING_DEPENDENCY with TECHNICAL_RETRY and nonnull due. SQL remains authority. No timer for null or terminal work. Startup/event/safety paths rediscover durable hints. This specifically addresses C technical retries; independent timed outbox lease/retry scheduling is not added in this increment.
- Single reader owns at most one cancellable hint per tenant; a channel wait is cancelled/awaited at the earliest due (bounded by safety interval), then rechecked against current UTC and normal SQL due fence. Never abandon a channel read or create one task/timer per receipt. Due tenants cannot starve behind event hints; after each sweep replace/remove the hint from SQL. Already-due remainder yields 250ms, failed sweep with due remainder yields 5s; failed discovery retries only the read after 5s, not a business command. These are scheduling hints, not changes to persisted retry timing/attempts. An active serial sweep may delay another tenant; no hard scheduler SLO.
- Real process shutdown cancels outstanding waits and ticker. No in-memory state is required to recover after restart. No new public endpoint, test-only production setting, or lock bypass.
