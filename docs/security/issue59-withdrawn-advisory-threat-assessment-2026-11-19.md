## 1. Upstream event and what it does NOT prove

- The [GitHub GHSA-fc5q-39xc-vjpf advisory](https://github.com/advisories/GHSA-fc5q-39xc-vjpf) was **withdrawn on 2026-11-18** after an upstream dispute that classifies untrusted-user-defined glob expressions as outside the supported trust boundary. The advisory page still lists `picomatch <=4.0.7`, **no patched release**, and a contradictory withdrawal sentence; see [the wording correction PR](https://github.com/github/advisory-database/pull/11405) and [upstream maintainer discussion](https://github.com/micromatch/picomatch/pull/235#issuecomment-6315749381).
- Withdrawal changes **advisory status**, not `picomatch@4.0.7` bytecode. Repeated-extglob patterns such as `+(*a)` can still cause expensive backtracking in an isolated reproduction. The existence of a pathological pattern is distinct from an exploitable untrusted-input path in this application.
- The official npm package has **no reviewed patched version established** by this assessment. Neither `@ryotsu/picomatch` nor `@rootio/picomatch` is accepted. PRs for alternative parser fixes upstream remain unmerged at this check.
- A full `npm audit` that turns green because GitHub removed an advisory **does not validate a parser patch** or grant permission to release production/PREPROD artifacts. Scanner feeds (npm, Snyk, OSV, NVD, vendors) can diverge after withdrawal.
