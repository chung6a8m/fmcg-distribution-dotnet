## BACKUP — independent SQL and off-host authority

- DBAs create/approve SQL Server FULL recovery and a nonexportable in-runtime backup encryption certificate whose **private key is separately, securely backed up and recoverable** under independently scoped Vault key versions; preserve old version for permitted historical decrypt, deny revoked versions. Establish least-privilege backup operator credential, separate encrypted off-host transfer identity and *different* restore/decrypt principal with audited access. Certificate and private-key material must never enter Git/CI artifacts, CLI arguments, logs or Docker images.
- Approve immutable off-host object store/versioning/retention/legal hold with B.8 Legal/Security, as applicable. Configure scheduled regular FULL at least daily, differential <=6h and LOG <=5m with alert on missing/late chains; scheduling is **outside this PR** and must be measured from completed backup UTC, not Cron definitions. Control Plane, independent revocation store, Vault metadata/key recovery and independent receiver outcome journal each need their own protected backup/restore strategy. A tenant backup alone is insufficient.
- The operator invokes `scripts/Invoke-App02B7Backup.ps1` from an approved PREPROD SQL administration host with named params: `TenantId`, `Kind`, `SqlInstance`, `ApprovedSqlInstance`, `ApprovedSqlServerName`, `SqlServerStageFile`, `EncryptionCertificate`, `ApprovedChangeRef`. With no `-Execute`, it prints a plan only. `-Execute` performs validated SQL encrypted staging backup + RESTORE VERIFYONLY only; requires current binding marker and FULL recovery and denies any server identity mismatch or missing certificate. No plaintext secrets or database selection by caller.
- Independently ship ciphertext to the separately approved off-host store using the approved private transfer mechanism, verify immutable object SHA-256 against source and retained version/LSN + SQL header metadata, record KeyId/Version/retired-revoked states, demonstrate authorized independent **restore/decrypt** identity can read it and wrong identity cannot. An encrypted local `.bak` file or untested off-host upload is **NOT** B03-01 PASS.
- Read SQL msdb backup history + media family headers independently and compare LSN chain/fork, FULL base, differential base and log gaps to actual timestamped files, not job configuration. On corrupt/gap/failed backup, revoked key or off-host unavailable: page incident, suspend restoration claims and record signed expected/actual/diff. Do not invent legal retention duration.

## CONTROLLED A RESTORE — safe barrier, no automatic reactivation

1. Independent Security suspends A via **current** B.4 authoritative Registry and denies A API/Worker/CASE/dispatch. Capture current external B.5 fence/epoch in an **independently durable rollback-resistant control store** and current B.3 sessions; this same-commit revocation bridge is not implemented (#53), so B.7 real safe restore is **currently BLOCKED**. Snapshot A/B physical DB IDs, full user-table hashes, approved A binding/version, independent receiver outcomes, key versions, current policy approvals and UTC+monotonic T0.
2. Independent DBA validates encrypted off-host FULL/diff/log chain and recovery point, unseals/decrypts using separately authorized **current historical-compatibility key** from Vault; RESTORE VERIFYONLY with CHECKSUM on each media. Use SQL `RESTORE DATABASE ... WITH NORECOVERY`, appropriate `MOVE`, `RESTORE DIFFERENTIAL ... WITH NORECOVERY`, LOG sequence with `STOPAT` when recoverable (abort on bulk-logged ambiguity), `WITH RECOVERY` **only in isolated nonroutable A restore target**, never directly overwrite the active DB or peer B. Never accept a restored Control Plane snapshot as current authority.
3. Compare restored `dbo.__PreprodTenantBinding` TenantId/BindingId/Version against current independent B.4 Registry and intended target, enforce exact physical name/instance ownership and deny wrong marker/adoption/swap; recheck independently anchored current B.5 revocation epoch, session/permission/membership and B.6 approval, then validated KeyId/Version. If any uncertain/missing, leave SUSPENDED, no initial-provisioning retry; preserve incident/CASE.
4. Reconcile APP-01 ledger/source and APP-02A durable receipt, dependency, CASE, inbox, outbox, immutable MessageId/EventId/SourceId and **independent receiver effect journal** for every pending/inflight item. COMMITTED with independent effect-count=1 is dedup; independently proven NOT_SENT with zero effect may resume with **same identity** only after approval; UNKNOWN/failed readback => HOLD/CASE/incident, **never** new-ID retry or outbound dispatch.
5. Independent reviewer validates full tenant A/B SQL before/after hashes, current Registry and Vault and authority at resume, rejection of stale JWT/refresh/Worker/CASE work, rollback/revoke race, safe API/Worker ready probe. A remains nonroutable until a separately approved, later B.4/B.5 activation CAS with current epoch; **B.7 source has no reactivation ability**.
6. Capture T0 first unavailable UTC and monotonic anchor, latest *independently* committed recovered witness timestamp/LSN, and monotonic T1 only after safe service reentry. Actual RPO = T0 UTC minus newest recovered committed event UTC; actual RTO = monotonic unsafe interval. Values outside **0..900 seconds RPO** or **0..14400 seconds RTO**, missing current key/witness or a failed negative check = **G-B03 FAIL**. SQL availability time alone never ends RTO. Independent security/DB reviewers sign source/fixture/backup-chain hashes, TestRunId, actor, environment, approval, artifacts and each B03-01..06 result.
