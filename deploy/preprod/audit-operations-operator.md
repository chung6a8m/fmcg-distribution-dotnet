# APP-02B.8 — Audit and Operations operator runbook

**PREPROD only, source-only implementation. No applied migration or operational admission is claimed.** Do not use this SQL on a production tenant or expose it through public API/Worker. [B.1 B04-01..06](../../docs/security/app-02b1-acceptance-evidence.md) and [B.8 contract](../../docs/roadmap/app-02b8-immutable-audit-operations.md) govern release.

1. **Preflight / DBA + Security:** obtain approved change, exact final source and SQL SHA, independently approved separate audit Control Plane database, tenant A/B Registry BindingId/version/current epochs, SQL server identity, named operator/reviewer, external Vault/anchor signer. Physical B.4/B.5 authority MUST reject suspended/revoked/foreign tenants. No inherited production access from a System Admin. Never run scripts on system/managed production databases.
2. **Migration:** operator runs `src/FmcgDms.Preprod.Operations/Migrations/20261118_001_immutable_audit.sql` manually under verified target database, replays for intact-state proof and checks mandatory tables/roles/triggers/procs. Script creates no actor, tenant, policy, schedule, retention, network endpoint or purge, and no API/Worker registration.
3. **Scoped access:** DBA alone maps vetted SQL logins in `dbo.B8WriterScope` with `TenantId` and minimum `CanAppend` or `CanHold`, then assigns `b8_writer` or `b8_hold` execute roles. Do not grant table SELECT/UPDATE/DELETE, db_owner, sysadmin, impersonation or secrets to workloads. Real actor/tenant mapping requires independent source binding; caller-provided audit IDs are not proof.
4. **Independent audit:** require redacted data only; never store JWT/refresh token/cookie, Vault keys, connection strings, PII or unrestricted exception messages. Independently export every tenant sequence/hash, sign a version-1 digest with separately held ECDSA P-256 key and securely archive immutable off-host anchor/receipt; test key-version rotation/revocation, missing anchor, dropped trigger, deleted tail, two-tenant peer no-write and verifier. **DB triggers alone cannot stop a privileged DBA.** Halt and escalate if off-host evidence is absent.
5. **OTel / operations:** configure/export ActivitySource/Meter via controlled OTel collector and link real API durable intake, Worker, SQL, inbox/outbox/CASE, lost ACK and original MessageId across restart. Independently approve alert thresholds/version for cross-tenant denial, refresh replay, backlog, recovery time or tamper; record triggered/received/ACK UTC, responsible owner, severity and escalation deadlines. A missing ACK is a failed delivery, not SUCCESS. Run incident drills with immutable IncidentId, owner handoff, runbook version, separate closeout reviewer and alternate escalation path.
6. **Legal hold & retention:** obtain explicit governing authority, jurisdiction, per-class retention (currently UNSET), separate Maker/Checker/reviewer, immutable archive manifest and external witness before any operator action. SQL `B8LegalHold` is append-only with no release or purge path; changes require a separate approved future migration. `B8RetentionGate` is **dry-run** and performs NO deletion. Any active hold or missing approval blocks purge. Never TTL-delete APP-02A durable receipts/CASE/source/inbox/outbox or APP-01 ledger/source, immutable audit, backup or legal evidence.
7. **Incident actions:** tamper/no anchor → freeze audit acceptance and preserve independent witness; refresh replay/tenant crossing → deny and verify security epoch; Worker lost ACK/UNKNOWN external effect → HOLD/CASE, original SourceId/MessageId only, no blind resend; pager ACK missing → escalate and record failed handoff; hold/purge attempt → deny and preserve before/after hashes. Physical drill and independently reviewed closeout required before any B.9 gate claim.

**Required independent handoff:** approved source/SQL SHA, migration/version, SQL grants and deny proofs, two physical tenant/peer fingerprints, captured chain/anchor receipts/key versions, actual traces, alert config and acknowledged deliveries, incident timeline/owner/reviewer, legal authority/hold/archive/purge manifest, restoration proof, TestRunId/artifact SHA, reviewed expected/actual/diff. Until then status is `PHYSICAL_PREPROD_NOT_VERIFIED / G-B04 NOT_RUN`; production/Pilot/B.9 cannot be claimed.
